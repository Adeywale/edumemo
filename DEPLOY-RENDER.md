# Deploying EduMemo to Render (Free Tier)

EduMemo is a long-running Node.js/Express server with a SQLite database and
disk-based file uploads, so it needs a real server process — static hosts
(GitHub Pages, Netlify, Vercel) will not work. Render's **free web service**
plan runs it as-is with HTTPS, a public URL, and no credit card.

> ⚠️ **Free-plan limits you should know before you start**
> 1. **Sleeps after ~15 minutes of inactivity** — the next visitor waits
>    ~50 seconds on a cold start. Fix: a free keep-warm pinger (step 6).
> 2. **No persistent disk** — the SQLite database and uploaded attachments
>    (pointed at `/tmp`) are **wiped on every restart/redeploy**. While the
>    instance stays warm, all data persists normally in memory + on disk.
>    The app's startup banner prints a warning confirming this at boot.
>    Only a paid disk (Render) / volume (Railway) or a self-managed VPS
>    (Oracle Cloud Always Free) gives true durability.

---

## Step 0 — Prerequisites

- The repo pushed to GitHub (secret files are already git-ignored:
  `.env`, `*.txt`, `*.sqlite` — verify with `git status` before pushing).
- A Gmail account with a **16-character App Password** (no spaces):
  <https://myaccount.google.com/apppasswords>
- VAPID keys for web push (generate once, reuse forever):
  ```bash
  npx web-push generate-vapid-keys
  ```

## Step 1 — Create the service from the Blueprint

1. Push this repo (with `render.yaml`) to GitHub.
2. On <https://dashboard.render.com> → **New → Blueprint** → pick the repo.
3. Render reads `render.yaml` and pre-fills the service: Node runtime,
   `npm ci` build, `npm start` start command, and all environment variables.

## Step 2 — Fill in the secret variables

Render will prompt for every `sync: false` variable in `render.yaml`.
You can also edit them later under **Environment**:

| Variable | What to put |
|---|---|
| `BASE_URL` | `https://<service-name>.onrender.com` (your Render URL, known after the first deploy — set it after the service is created) |
| `SMTP_USER` / `SMTP_FROM_EMAIL` | your sending Gmail address |
| `SMTP_PASSWORD` | the 16-char Gmail App Password (no spaces) |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | output of `npx web-push generate-vapid-keys` |
| `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` | first Super Admin login (created only on an empty database) |

`SESSION_SECRET` is auto-generated by Render (`generateValue: true`).

## Step 3 — First deploy

- Click **Apply** / **Create Resources**. Build takes a few minutes.
- Watch **Logs** for the startup banner. A healthy boot shows:
  ```
  Database file: /tmp/database.sqlite
  Uploads folder: /tmp/uploads
  Persistent storage detected: yes
  SMTP (email) configured: yes
  Web Push (VAPID) configured: yes
  ```
  then `Empty database detected — seeding academic structure and admin
  account...` on the very first boot.
- Open `https://<your-app>.onrender.com` → it redirects to `/login`.
  Sign in with `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD`.

## Step 4 — Set BASE_URL (if you skipped it)

After the first deploy you know the real domain: set `BASE_URL` to
`https://<your-app>.onrender.com` and redeploy. This makes the links inside
password-reset and new-memo emails point to the public domain.

## Step 5 — HTTPS (automatic)

Render's `.onrender.com` domain serves HTTPS by default, which is exactly
what the service worker and Web Push require. Nothing to configure.

## Step 6 — Keep it warm (free)

Free services sleep after 15 idle minutes, causing slow cold starts (and a
data reset, since the disk is ephemeral). Create a free pinger:

1. Sign up at <https://cron-job.org> (or UptimeRobot).
2. Create a job hitting `https://<your-app>.onrender.com/api/config`
   (unauthenticated 200 JSON endpoint) **every 10 minutes**.

This keeps the instance alive 24/7 within the free tier (750 instance-hours
per month is enough for one service).

## Step 7 — Test the critical flows

| Flow | How |
|---|---|
| Admin portal | `/admin/login` → dashboard loads |
| Memo + attachment | Create a memo with a PDF/JPG attachment → verify it downloads |
| Email | Publish a memo → recipients receive the "View Memo" email with correct `BASE_URL` links |
| Web push | Subscribe a browser → publish a memo → notification arrives |
| Password reset | `/forgot-password` → email link opens the reset page |

## Troubleshooting

- **`Persistent storage detected: NO` in the banner** — `DATABASE_PATH` /
  `UPLOAD_DIR` are not set. Check the Environment tab matches `render.yaml`.
- **Emails not sending** — Gmail requires the *App Password*, not your login
  password, and with no spaces. The banner must say `SMTP configured: yes`.
- **Push never delivered** — banner must say `Web Push (VAPID) configured:
  yes`; otherwise regenerate keys and redeploy.
- **Deploy succeeded but everything vanished** — expected on the free plan
  after a restart/redeploy (ephemeral `/tmp`); see the warning at the top.
- **Slow first load** — that's the cold start after sleeping; keep-warm
  pinger in Step 6 removes it.

## Upgrading later

When real usage demands durability, either:
- **Render**: switch to a paid plan + attach a **Disk** (e.g. mount `/data`),
  then set `DATABASE_PATH=/data/database.sqlite` and `UPLOAD_DIR=/data/uploads`; or
- **Railway** (~$5/mo): your codebase auto-detects `RAILWAY_VOLUME_MOUNT_PATH`
  the moment a Volume is attached — no code changes needed; or
- **Oracle Cloud Always Free** (a real free VPS): full persistent disk and no
  sleeping, but you manage Node, HTTPS, and process supervision yourself.
